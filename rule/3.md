# Математическая модель оптимальной и компактной компоновки AutoTrace

## 1. Назначение модели

Необходимо формализовать построение схемы как задачу дискретно-непрерывной многокритериальной оптимизации.

На входе задан ориентированный граф:

[
G=(V,E)
]

где:

* (V={v_1,\ldots,v_n}) — блоки;
* (E={e_1,\ldots,e_m}) — соединения;
* каждый блок имеет размеры, порты и ограничения;
* каждое соединение связывает конкретные порты двух блоков.

Требуется найти:

1. размеры блоков;
2. положение блоков;
3. порядок блоков;
4. распределение адаптивных портов;
5. положение портов;
6. ортогональные маршруты;
7. routing channels;
8. положение подписей;

так, чтобы схема была одновременно:

* корректной;
* компактной;
* хорошо читаемой;
* преимущественно направленной слева направо;
* с минимальным количеством пересечений;
* с минимальным количеством поворотов;
* с короткими соединениями;
* с минимальными пустотами;
* с хорошим выравниванием связанных портов.

---

# 2. Главное разделение ограничений

Все требования делятся на:

[
\boxed{\text{Hard Constraints}}
]

и

[
\boxed{\text{Soft Objectives}}
]

Hard constraints никогда не должны нарушаться.

Soft objectives используются для выбора лучшего решения среди допустимых.

Это принципиально лучше модели:

[
F=\sum_i w_i P_i
]

где даже геометрически запрещённое состояние просто получает большой штраф.

Например:

[
\text{blockOverlap}=0
]

должно быть constraint, а не penalty.

---

# 3. Переменные блоков

Для каждого блока (i):

[
x_i,y_i
]

— координаты левого верхнего угла.

Размеры:

[
w_i,h_i
]

Если AutoSize отключён:

[
w_i=\hat w_i,\qquad h_i=\hat h_i
]

Если AutoSize разрешён:

[
w_i\ge w_i^{min}
]

[
h_i\ge h_i^{min}
]

где минимальные размеры определяются геометрией содержимого и портов.

---

# 4. Центр блока

Удобно определить:

[
c_i^x=x_i+\frac{w_i}{2}
]

[
c_i^y=y_i+\frac{h_i}{2}
]

Центры используются для:

* layering;
* alignment;
* symmetry;
* compactness;
* ordering.

---

# 5. Routing envelope

Для каждого блока определяется расширенный прямоугольник:

[
R_i=
[x_i-\delta_i,,
x_i+w_i+\delta_i]
\times
[y_i-\delta_i,,
y_i+h_i+\delta_i]
]

где:

[
\delta_i
]

— routing clearance.

Маршрутам запрещено пересекать (R_i), кроме собственных port stubs.

---

# 6. Математическая модель порта

Для порта (p) блока (i):

[
P_{ip}=(x_{ip},y_{ip})
]

Если сторона `LEFT`:

[
x_{ip}=x_i
]

[
y_{ip}=y_i+t_{ip}h_i
]

Если `RIGHT`:

[
x_{ip}=x_i+w_i
]

[
y_{ip}=y_i+t_{ip}h_i
]

Если `TOP`:

[
x_{ip}=x_i+t_{ip}w_i
]

[
y_{ip}=y_i
]

Если `BOTTOM`:

[
x_{ip}=x_i+t_{ip}w_i
]

[
y_{ip}=y_i+h_i
]

где:

[
0<t_{ip}<1
]

---

# 7. Fixed Port

Для fixed-порта:

[
t_{ip}=\hat t_{ip}
]

является жёстким ограничением.

---

# 8. Adaptive Port

Для adaptive-порта:

[
t_{ip}
]

является оптимизируемой переменной.

При этом:

[
t_{min}\le t_{ip}\le t_{max}
]

Например:

[
0.08\le t_{ip}\le0.92
]

---

# 9. Ограничение расстояния между портами

Для двух соседних портов одной стороны:

[
|s_p-s_q|\ge d_{port}
]

где (s) — координата вдоль стороны блока.

Для вертикальной стороны:

[
s_p=y_p
]

Для горизонтальной:

[
s_p=x_p
]

---

# 10. Сохранение порядка портов

Если:

[
order(p)<order(q)
]

то:

[
s_p+d_{port}\le s_q
]

Это предотвращает перестановку семантически связанных контактов.

---

# 11. Группировка портов

Для портов одной группы (g) вводится стоимость разброса:

[
C_{group}
=========

\sum_g
\left(
\max_{p\in g}s_p
----------------

\min_{p\in g}s_p
\right)
]

Минимизация этой величины удерживает:

* SPI;
* I²C;
* UART;
* power group;
* buses

рядом.

---

# 12. Layer variable

Каждому блоку назначается дискретный слой:

[
l_i\in\mathbb{Z}_{\ge0}
]

Для нормального forward-edge (i\rightarrow j):

[
l_j\ge l_i+1
]

Для edge с dummy nodes допустимо:

[
l_j>l_i+1
]

---

# 13. Связь слоя и координаты X

В простейшей модели:

[
x_i=X_{l_i}
]

где (X_l) — координата слоя.

Более гибко:

[
|x_i-X_{l_i}|\le\epsilon_x
]

Это позволяет небольшой локальный сдвиг.

---

# 14. Ширина межслойного пространства

Для соседних слоёв:

[
X_{l+1}
\ge
X_l+W_l+C_l
]

где:

[
W_l=\max_{i:l_i=l}w_i
]

а (C_l) — ширина routing channel.

---

# 15. Адаптивная ширина routing channel

Пусть между слоями проходит (q_l) независимых tracks.

Тогда:

[
C_l
===

C_0
+
q_l p_t
+
2c
]

где:

* (C_0) — минимальное пространство;
* (p_t) — pitch трасс;
* (c) — clearance.

Таким образом пространство резервируется только там, где оно реально необходимо.

---

# 16. Запрет пересечения блоков

Для любых блоков (i\neq j) должно выполняться хотя бы одно условие:

[
x_i+w_i+g_x\le x_j
]

или

[
x_j+w_j+g_x\le x_i
]

или

[
y_i+h_i+g_y\le y_j
]

или

[
y_j+h_j+g_y\le y_i
]

Это классическое disjunctive constraint.

В MILP оно реализуется бинарными переменными.

---

# 17. Bounding Box всей схемы

Определяются:

[
X_{min}=\min_i x_i
]

[
X_{max}=\max_i(x_i+w_i)
]

[
Y_{min}=\min_i y_i
]

[
Y_{max}=\max_i(y_i+h_i)
]

Тогда:

[
W_D=X_{max}-X_{min}
]

[
H_D=Y_{max}-Y_{min}
]

и площадь схемы:

[
A_D=W_DH_D
]

---

# 18. Почему нельзя минимизировать только площадь

Если минимизировать исключительно:

[
A_D
]

алгоритм может получить чрезмерно узкую и высокую схему:

[
W_D\ll H_D
]

либо наоборот.

Поэтому используется одновременно:

[
C_{bbox}
========

\alpha W_D
+
\beta H_D
+
\gamma W_DH_D
]

---

# 19. Aspect Ratio

Для большинства инженерных схем предпочтительно:

[
W_D\ge H_D
]

и некоторый целевой aspect:

[
r^*=\frac{W_D}{H_D}
]

Например:

[
r^*\approx1.5-2.5
]

Дополнительный штраф:

[
C_{aspect}
==========

\left|
\log
\frac{W_D/H_D}{r^*}
\right|
]

Логарифмическая форма симметрично штрафует слишком широкие и слишком высокие схемы.

---

# 20. Реальная компактность

Компактность нельзя измерять только bounding box.

Введём:

[
A_B=\sum_i w_ih_i
]

— суммарную площадь блоков.

Density:

[
D=
\frac{A_B}{A_D}
]

Чем выше (D), тем компактнее схема.

Но (D\rightarrow1) также нежелательно, потому что необходимо пространство для трассировки.

Поэтому вводится целевая плотность:

[
D^*
]

например:

[
0.35\le D^*\le0.65
]

в зависимости от плотности графа.

---

# 21. Адаптивная целевая плотность

Можно определить:

[
\rho_G=\frac{|E|}{|V|}
]

и вычислять:

[
D^*(\rho_G)
===========

## D_{max}

k\rho_G
]

То есть:

* мало связей → блоки можно поставить плотнее;
* много связей → требуется больше routing space.

Например:

[
D^*
===

clamp(
0.65-0.06\rho_G,,
0.30,,
0.60
)
]

---

# 22. Штраф плотности

[
C_{density}
===========

(D-D^*)^2
]

Это лучше обычной минимизации площади.

Система стремится не к минимальной физически возможной площади, а к **оптимальной плотности**.

---

# 23. Пустоты внутри схемы

Большой bounding box может содержать огромные пустые зоны.

Для сеточных ячеек введём occupancy:

[
o_k\in{0,1}
]

Тогда можно оценивать internal void:

[
A_{void}
========

## A_D

## A_B

A_{routingUsed}
]

и минимизировать:

[
C_{void}=\frac{A_{void}}{A_D}
]

Особенно важно штрафовать крупные связные пустоты между слоями.

---

# 24. Edge Span

Для каждой связи (e=(i,j)):

[
S_e=|l_j-l_i|
]

Минимизируем:

[
C_{span}
========

\sum_e(S_e-1)
]

Это уменьшает количество длинных межслойных связей.

---

# 25. Port Alignment

Для edge между facing ports:

[
e=(p_s,p_t)
]

при horizontal flow:

[
A_e=|y_{p_s}-y_{p_t}|
]

Общая стоимость:

[
C_{align}
=========

\sum_e \omega_e A_e
]

---

# 26. Нормализованный alignment

Чтобы большие схемы не получали автоматически огромный cost:

[
\hat A_e=
\frac{|y_s-y_t|}
{H_D+\varepsilon}
]

и:

[
C_{align}
=========

\frac{1}{|E|}
\sum_e \hat A_e
]

---

# 27. Reward за полностью прямую связь

Определим:

[
z_e^{straight}\in{0,1}
]

где:

[
z_e^{straight}=1
]

если соединение можно провести одним прямым сегментом.

Тогда:

[
C_{straight}
============

-\sum_e\omega_e z_e^{straight}
]

Или, в нормализованной форме:

[
Q_{straight}
============

\frac{\sum_e z_e^{straight}}{|E|}
]

которую нужно максимизировать.

---

# 28. Модель маршрута

Маршрут edge (e):

[
R_e=
(P_e^0,P_e^1,\ldots,P_e^{k_e})
]

где каждый сегмент ортогонален:

[
x_j=x_{j+1}
]

или

[
y_j=y_{j+1}
]

---

# 29. Длина соединения

[
L_e=
\sum_{k=0}^{n_e-1}
\left(
|x_{k+1}-x_k|
+
|y_{k+1}-y_k|
\right)
]

Общая длина:

[
L_{total}
=========

\sum_e\omega_e L_e
]

---

# 30. Нормализованная длина соединения

Лучше сравнивать фактический маршрут с Manhattan lower bound:

[
L_e^{min}
=========

|x_s-x_t|
+
|y_s-y_t|
]

Тогда:

[
R_e^L
=====

\frac{L_e}
{L_e^{min}+\varepsilon}
]

Идеальное значение:

[
R_e^L=1
]

---

# 31. Bend Count

Для edge:

[
B_e=k_e-1
]

после удаления collinear points.

Общее:

[
B=
\sum_e B_e
]

Нормализованно:

[
C_{bend}
========

\frac{1}{|E|}
\sum_e B_e
]

---

# 32. Усиленный штраф за много поворотов

Для читаемости предпочтительнее нелинейный penalty:

[
P_B(B_e)
========

B_e+\lambda_B B_e^2
]

Например:

[
P_B(1)=1.5
]

[
P_B(2)=4
]

[
P_B(4)=12
]

Так лестничные маршруты становятся очень дорогими.

---

# 33. Crossing Count

Для двух разных маршрутов:

[
X_{ef}
======

#{
\text{perpendicular intersections}
}
]

Общее:

[
X=
\sum_{e<f}X_{ef}
]

---

# 34. Crossing penalty

Пересечение обычно намного хуже небольшой дополнительной длины.

Поэтому:

[
C_{cross}
=========

\sum_{e<f}
\omega_{ef}X_{ef}
]

где, например:

* signal × signal = 1;
* signal × bus = 2;
* bus × bus = 4;
* clock crossing = повышенный коэффициент.

---

# 35. Collinear overlap

Для независимых edge:

[
O_{ef}
======

length(
R_e\cap R_f
)
]

Hard constraint:

[
O_{ef}=0
]

если они не принадлежат общей net/bus trunk.

---

# 36. Congestion

Пусть routing space разбит на ресурсы (r).

Для ресурса:

[
u_r=
\sum_e I(e\ uses\ r)
]

Capacity:

[
cap_r
]

Overflow:

[
overflow_r=
\max(0,u_r-cap_r)
]

Тогда:

[
C_{congestion}
==============

\sum_r
overflow_r^2
]

Квадратичная функция важна:

двойная перегрузка должна быть значительно хуже двух слабых перегрузок.

---

# 37. Proximity между трассами

Даже если трассы не накладываются, слишком маленькое расстояние нежелательно.

Для сегментов:

[
d_{ef}
======

distance(segment_e,segment_f)
]

Penalty:

[
P_{prox}(d)
===========

\begin{cases}
\left(\frac{d_{pref}-d}{d_{pref}}\right)^2,
& d<d_{pref}\
0,&d\ge d_{pref}
\end{cases}
]

---

# 38. Port exit quality

Каждый route должен первые:

[
L_{stub}
]

пикселей двигаться по нормали порта.

Это hard constraint:

[
P_e^1-P_e^0
===========

\lambda n_s
]

где:

[
\lambda>0
]

Для target:

[
P_e^{k}-P_e^{k-1}
=================

-\mu n_t
]

---

# 39. Feedback Edge

Feedback-ребро должно прокладываться отдельно.

Для feedback edge вводится preferred external corridor.

Например:

[
y_{feedback}
<
Y_{min}-g_f
]

или:

[
y_{feedback}

>

Y_{max}+g_f
]

Это предотвращает прохождение обратных связей через основной поток.

---

# 40. Вертикальный порядок блоков

Для блока (i) внутри layer:

[
o_i
]

— дискретный порядок.

Для соседних элементов:

[
y_{i_{k+1}}
\ge
y_{i_k}
+
h_{i_k}
+
g_{node}
]

---

# 41. Barycentric objective

Для блока (i):

[
b_i
===

\frac{
\sum_{j\in N(i)}
\omega_{ij}c_j^y
}{
\sum_{j\in N(i)}\omega_{ij}
}
]

Затем:

[
C_{bary}
========

\sum_i
|c_i^y-b_i|
]

Это удерживает блок около вертикального центра его связей.

---

# 42. Port-aware barycenter

Лучше использовать не центр соседнего блока, а связанный port.

[
b_i^{port}
==========

\frac{
\sum_{e=(i,j)}
\omega_e y_{p_j}
}{
\sum_e\omega_e
}
]

и:

[
C_{portBary}
============

\sum_i
|c_i^y-b_i^{port}|
]

Это значительно повышает число прямых соединений.

---

# 43. Symmetry

Для структурно похожих блоков можно вводить symmetry group.

Например два одинаковых subsystem:

[
S_1,S_2
]

Penalty:

[
C_{sym}
=======

|spacing_1-spacing_2|
+
|alignment_1-alignment_2|
]

Symmetry является soft objective и не должна ухудшать routing.

---

# 44. Alignment блоков

Можно стимулировать совпадение координат:

[
x_i=x_j
]

для одного layer,

или:

[
y_i=y_j
]

для логически связанных горизонтальных рядов.

Мягкий вариант:

[
C_{gridAlign}
=============

\sum_{(i,j)\in A}
|y_i-y_j|
]

---

# 45. Snap to grid

Для координат:

[
x_i=k_i^xg
]

[
y_i=k_i^yg
]

где:

[
k_i^x,k_i^y\in\mathbb Z
]

а (g) — grid size.

Это существенно уменьшает пространство поиска.

---

# 46. Compactness внутри каждого layer

Пусть layer (l) содержит блоки:

[
V_l
]

Высота слоя:

[
H_l
===

## \max_{i\in V_l}(y_i+h_i)

\min_{i\in V_l}y_i
]

Использованная блоками высота:

[
B_l=\sum_{i\in V_l}h_i
]

Gap area:

[
G_l=H_l-B_l
]

Тогда:

[
C_{layerCompact}
================

\sum_l G_l
]

Это очень эффективный локальный критерий compactness.

---

# 47. Balanced Layering

Необходимо предотвращать появление одного слоя с чрезмерным числом блоков.

Пусть:

[
n_l=|V_l|
]

Среднее:

[
\bar n=
\frac{|V|}{N_L}
]

Penalty:

[
C_{balance}
===========

\sum_l(n_l-\bar n)^2
]

Но этот критерий должен иметь низкий приоритет: topology важнее красоты.

---

# 48. Width-aware Layer Balance

Простого количества блоков недостаточно.

Лучше использовать:

[
M_l
===

\sum_{i\in V_l}h_i
+
(n_l-1)g
]

и:

[
C_{layerBalance}
================

variance(M_l)
]

---

# 49. Global objective

Наивная модель:

[
F=
w_A C_{area}
+
w_W C_{wire}
+
w_B C_{bend}
+
w_X C_{cross}
+\ldots
]

работает, но имеет недостаток:

результат сильно зависит от выбора весов.

Для AutoTrace предпочтительнее **лексикографическая оптимизация**.

---

# 50. Лексикографическая модель

Оптимизация выполняется последовательно.

## Уровень P0 — correctness

Обязательно:

[
BlockOverlap=0
]

[
WireBlockCollision=0
]

[
InvalidPortNormal=0
]

[
IllegalOverlap=0
]

---

## Уровень P1 — topology

Минимизировать:

[
X
]

пересечения.

Затем:

[
S=\sum_e(S_e-1)
]

длинные layer spans.

[

повороты.

прямые connections.

# 51. (\varepsilon)-constraint optimization

Чтобы улучшение compactness не ухудшало crossings, после нахождения лучшего числа пересечений:

[
X^*
]

следующий этап решается при constraint:

[
X\le X^*
]

После bend optimization:

[
B\le B^*+\varepsilon_B
]

Например можно разрешить:

[
\varepsilon_B=1
]

если это даёт заметно более компактную схему.

# 52. Практическая глобальная функция

Для локальных итераций можно использовать нормализованный score:

[
F=
\lambda_1\hat X
+
\lambda_2\hat B
+
\lambda_3\hat L
+
\lambda_4\hat C
+
\lambda_5\hat A
+
\lambda_6\hat D
+
\lambda_7\hat P
]

где:

* (\hat X) — crossings;
* (\hat B) — bends;
* (\hat L) — normalized wire length;
* (\hat C) — congestion;
* (\hat A) — area;
* (\hat D) — density deviation;
* (\hat P) — port misalignment.

Все компоненты должны быть нормализованы примерно в диапазон:

[
[0,1]
]

# 53. Предлагаемые веса локального optimizer

После выполнения hard constraints:

[
F=
0.28X_n
+
0.20B_n
+
0.15C_n
+
0.14A_n
+
0.10P_n
+
0.08L_n
+
0.05S_n
]

где:

* (X_n) — normalized crossings;
* (B_n) — bends;
* (C_n) — congestion;
* (A_n) — compactness;
* (P_n) — port alignment;
* (L_n) — wire length;
* (S_n) — symmetry/aesthetic score.

Это стартовая конфигурация, а не математически универсальная константа.

# 54. Нормализация площади

Использовать абсолютную площадь неудобно.

Введём theoretical block area:

[
A_0=\sum_iw_ih_i
]

Тогда:

[
A_n=
\frac{A_D}{A_0}
]

Например:

[
A_n=2
]

означает, что bounding box вдвое больше суммарной площади блоков.

---

# 55. Нормализация длины

[
L_n=
\frac{
\sum_eL_e
}{
\sum_eL_e^{min}
}
-1
]

Идеальное значение:

[
L_n=0
]

---

# 56. Нормализация bend count

Можно использовать:

[
B_n=
\frac{
\sum_eB_e
}{
2|E|+\varepsilon
}
]

Если среднее число bend = 2:

[
B_n\approx1
]

---

# 57. Нормализация crossing count

Поскольку число потенциальных пар:

[
O(E^2)
]

используем:

[
X_n=
\frac{2X}{|E|(|E|-1)+\varepsilon}
]

Для UI дополнительно показывать абсолютное (X).

---

# 58. Compactness Score

Для пользователя удобно вывести отдельную метрику:

[
Q_C
===

100
\cdot
\left[
\alpha
\frac{D}{D^*}
+
\beta
\frac{1}{1+A_{void}/A_D}
+
\gamma
\frac{1}{1+C_{aspect}}
\right]
]

с ограничением:

[
0\le Q_C\le100
]

Но для optimizer лучше использовать исходные компоненты, а не агрегированный UI score.

---

# 59. Readability Score

Можно определить:

[
Q_R=
100
\cdot
\exp(
-----

[
aX_n
+bB_n
+cC_n
+dP_n
]
)
]

Преимущество экспоненты:

несколько серьёзных нарушений быстро снижают оценку.

# 60. Общий Quality Score

Для отображения пользователю:

[
Q=
Q_{valid}
\cdot
\left(
0.40Q_R
+
0.25Q_C
+
0.20Q_{route}
+
0.15Q_{label}
\right)
]

где:

[
Q_{valid}=
\begin{cases}
1,&\text{hard constraints fulfilled}\
0,&\text{otherwise}
\end{cases}
]

То есть схема с геометрической ошибкой не может получить высокий score.

---

# 61. Почему точная глобальная оптимизация практически невозможна

Полная задача одновременно включает:

* graph layering;
* crossing minimization;
* rectangle packing;
* orthogonal routing;
* port assignment;
* label placement.

Отдельные подзадачи уже NP-hard.

Поэтому полный глобальный optimum для больших схем вычислять практически невозможно.

Нельзя использовать один универсальный:

[
MILP
]

для тысяч блоков.

---

# 62. Правильная математическая стратегия

Использовать hierarchical decomposition:

```text id="azx9fy"
Topology
   ↓
Layering
   ↓
Ordering
   ↓
Port optimization
   ↓
Coordinate assignment
   ↓
Compaction
   ↓
Routing
   ↓
Congestion optimization
   ↓
Local co-optimization
```

Каждый этап решает меньшую математическую задачу.

---

# 63. Level 1 — Topological optimization

Определить:

[
l_i
]

и временные feedback edges.

Цели:

[
\min C_{span}
]

[
\min N_{dummy}
]

при корректном DAG.

---

# 64. Level 2 — Ordering optimization

Для каждого слоя определить permutation:

[
\pi_l
]

Цель:

[
\min X(\pi)
]

Использовать:

* barycenter;
* median;
* transpose;
* sifting.

---

# 65. Level 3 — Continuous coordinate optimization

При фиксированном порядке оптимизируются:

[
y_i
]

и adaptive port positions:

[
t_p
]

Цель:

[
\min
[
C_{align}
+
C_{compact}
+
C_{bary}
]
]

при:

[
no-overlap
]

и:

[
port-spacing
]

Эта задача значительно проще общей.

---

# 66. Level 4 — Routing

При фиксированных блоках решается:

[
\min
[
L
+
\lambda_B B
+
\lambda_C C_{congestion}
+
\lambda_X X
]
]

через:

* A*;
* negotiated congestion;
* rip-up/reroute.

---

# 67. Level 5 — Joint refinement

После routing можно разрешить небольшие перемещения блоков:

[
|\Delta x_i|\le r_x
]

[
|\Delta y_i|\le r_y
]

и port shifts:

[
|\Delta t_p|\le r_p
]

если они уменьшают глобальный cost.

---

# 68. Trust Region

Для стабильности layout используется trust region.

После каждой глобальной итерации:

[
|x_i^{new}-x_i^{old}|
\le R_x
]

[
|y_i^{new}-y_i^{old}|
\le R_y
]

Это предотвращает визуальное «прыганье» схемы после небольшого изменения.

---

# 69. Mental Map Preservation

При редактировании существующей схемы вводится:

[
C_{stability}
=============

\sum_i
\omega_i
\left[
(x_i-x_i^{old})^2
+
(y_i-y_i^{old})^2
\right]
]

Для незатронутых блоков:

[
\omega_i
]

должен быть большим.

Для изменённой области — маленьким.

---

# 70. Локальная оптимизация

При изменении блока (v) создаётся neighborhood:

[
N_k(v)
]

Например все блоки на расстоянии:

[
k=2
]

по графу.

Оптимизируются только:

[
V_{local}=N_k(v)
]

Остальные координаты фиксируются.

---

# 71. Dirty Region

В геометрическом пространстве:

[
D=
BBox(oldGeometry\cup newGeometry)
\oplus margin
]

Перетрассировке подлежат edge:

[
E_D=
{
e:R_e\cap D\neq\varnothing
}
]

Это позволяет добиться интерактивной работы.

---

# 72. Математическая модель port assignment

Если adaptive port может выбирать сторону, вводятся бинарные переменные:

[
z_{ps}\in{0,1}
]

где:

[
s\in
{L,R,T,B}
]

Constraint:

[
\sum_s z_{ps}=1
]

Если сторона запрещена:

[
z_{ps}=0
]

---

# 73. Цена выбора стороны

Для связи (p\rightarrow q):

[
C_{side}
========

C_{orientation}
+
C_{distance}
+
C_{crossPrediction}
]

Например для global flow LEFT→RIGHT:

[
RIGHT_{source}
+
LEFT_{target}
]

получают минимальный penalty.

---

# 74. Предварительная оценка crossing без routing

Для edge между слоями можно использовать инверсию port orders.

Две связи:

[
e_1=(a,b)
]

[
e_2=(c,d)
]

вероятно пересекутся, если:

[
order(a)<order(c)
]

и:

[
order(b)>order(d)
]

Это позволяет оптимизировать adaptive ports до запуска A*.

---

# 75. Bus-aware optimization

Для группы edge одной bus:

[
E_g
]

вместо независимого routing можно оптимизировать trunk.

Пусть trunk:

[
T_g
]

Тогда:

[
C_{bus}
=======

L(T_g)
+
\sum_{e\in E_g}
L(branch_e)
+
\lambda
C_{branchCrossing}
]

Это лучше, чем независимо минимизировать каждый wire.

---

# 76. Hierarchical blocks

Для subsystem определяется собственный bounding box:

[
B_s
]

и внутренний graph:

[
G_s
]

Глобальный layout работает с subsystem как с supernode.

Затем отдельно оптимизируется внутреннее содержимое.

Это резко снижает сложность:

[
G
\rightarrow
G_{macro}
+
\sum_sG_s
]

---

# 77. Оптимизация размера блоков

Для AutoSize использовать:

[
w_i
===

\max
(
w_i^{text},
w_i^{ports},
w_i^{content}
)
]

[
h_i
===

\max
(
h_i^{text},
h_i^{ports},
h_i^{content}
)
]

Но можно разрешить optimizer выбирать между горизонтальным и вертикальным увеличением.

---

# 78. Aspect penalty отдельного блока

Чтобы блок не превращался в чрезмерно длинный rectangle:

[
r_i=\frac{w_i}{h_i}
]

Penalty:

[
C_{blockAspect}
===============

\sum_i
\left|
\log\frac{r_i}{r_i^*}
\right|
]

---

# 79. Стоимость увеличения блока

[
C_{resize}
==========

\sum_i
[
(w_i-w_i^{min})
(h_i-h_i^{min})
]
]

или проще:

[
C_{resize}
==========

\sum_i
[
(w_i-w_i^{min})
+
(h_i-h_i^{min})
]
]

Таким образом AutoSize не раздувает компоненты без необходимости.

---

# 80. Оптимальная формулировка компактности

Для AutoTrace предлагается определять compactness не как:

[
\min A_D
]

а как:

[
\boxed{
\min C_{compact}
================

\lambda_A A_n
+
\lambda_V C_{void}
+
\lambda_D C_{density}
+
\lambda_L C_{layerCompact}
+
\lambda_R C_{aspect}
}
]

при строгом условии:

[
routingFeasible=true
]

Это главное отличие от обычного rectangle packing.

---

# 81. Routing-aware compactness

Два layout могут иметь одинаковую площадь, но один практически невозможно трассировать.

Поэтому вводится:

[
C_{routeSpace}
==============

\sum_c
\max(0,
requiredTracks_c
----------------

availableTracks_c
)^2
]

И только layout с:

[
C_{routeSpace}=0
]

считается полноценно feasible.

---

# 82. Minimum Cut Capacity Constraint

Для критического routing corridor (c):

[
availableTracks_c
\ge
requiredTracks_c
]

где:

[
availableTracks_c
=================

\left\lfloor
\frac{W_c-2clearance}{trackPitch}
\right\rfloor
]

Это позволяет заранее не сжимать слои слишком сильно.

---

# 83. Значение оптимальной ширины channel

Для (n_c) трасс:

[
W_c^{min}
=========

2C
+
(n_c-1)p
+
w_t
]

где:

* (C) — side clearance;
* (p) — track pitch;
* (w_t) — wire width.

---

# 84. Vertical channel capacity

Аналогично:

[
H_c^{min}
=========

2C
+
(n_c-1)p
+
w_t
]

Таким образом compactness становится **routing-aware**, а не purely geometric.

Необходимо хранить:


а не последний state.

Следовательно optimizer может автоматически определять необходимую плотность.

# 101. Масштабируемость

Для (N) блоков не следует проверять все пары:

[
O(N^2)
]

Для collision detection использовать spatial index:

[
O(N\log N)
]

или близко к:

[
O(N)
]

для uniform grid.

---

# 102. Crossing evaluation

Наивный вариант:

[
O(E^2)
]

Для больших схем использовать:

* sweep line;
* interval tree;
* spatial hash.

Целевое:

[
O((E+K)\log E)
]

где (K) — реальное число пересечений.

---

# 103. Основной математический принцип

Оптимальная схема — это не схема с минимальной площадью.

Правильное определение:

[
\boxed{
\text{Optimal Layout}
=====================

\text{minimum-area feasible layout}
}
]

при ограничениях на:

[
\boxed{
routing\ quality
+
readability
+
topology
+
stability
}
]

То есть сначала схема должна быть **хорошо трассируемой**, а затем максимально сжиматься.

---

# 104. Определение максимально компактного допустимого layout

Можно формально определить:

[
A^*
===

\min A_D
]

при:

[
X\le X_{max}
]

[
B\le B_{max}
]

[
C_{congestion}=0
]

[
BlockOverlap=0
]

[
WireBlockCollision=0
]

[
D\le D_{max}
]

Таким образом задача compactness превращается из субъективной в измеримую.

# 105. Рекомендуемая модель AutoTrace

Для production рекомендуется использовать комбинацию:

```text id="c0dk2l"
Sugiyama
+
port-aware crossing minimization
+
constraint coordinate solver
+
routing-capacity-aware compaction
+
orthogonal A*
+
negotiated congestion
+
rip-up/reroute
+
local coordinate refinement
+
incremental compaction
```

а не пытаться решать всю задачу одним solver.

# 106. Финальный цикл оптимизации

```text id="jzw9fa"
S0 = InitialLayout(G)

BEST = S0

for outer_iteration:

    S = OptimizeLayers(S)

    S = OptimizeOrdering(S)

    S = OptimizePorts(S)

    S = OptimizeCoordinates(S)

    S = CompactWithRoutingCapacity(S)

    S = Route(S)

    S = NegotiateCongestion(S)

    S = CleanupRoutes(S)

    S = OptimizeCoordinatesAgainstRoutes(S)

    S = CompactUnusedSpace(S)

    S = RerouteDirtyRegions(S)

    S = PlaceLabels(S)

    Q = Evaluate(S)

    if Q better than BEST:
        BEST = S

    if converged:
        break

return BEST
```

---

# 107. Наиболее важное отличие модели

Обычный graph layout решает:

[
\text{где поставить вершины?}
]

AutoTrace должен решать более сложную задачу:

[
\boxed{
\text{
где поставить блоки так,
чтобы их реальные порты
можно было качественно соединить
в минимально необходимом пространстве
}
}
]

Поэтому port geometry и routing capacity должны участвовать в математической модели уже во время placement, а не только после него.

---

# 108. Итоговая формула концепции

В наиболее компактном виде модель можно представить:

[
\boxed{
S^*
===

\arg\min_{S\in\mathcal F}
\left[
C_{topology}
+
C_{routing}
+
C_{compactness}
+
C_{stability}
+
C_{aesthetics}
\right]
}
]

где:

[
\mathcal F
]

— множество всех геометрически и семантически допустимых схем.

Приоритет:

[
\boxed{
Correctness
\succ
Crossings
\succ
Congestion
\succ
Bends
\succ
Alignment
\succ
Compactness
\succ
Wirelength
\succ
Aesthetics
}
]

Это и должно являться математической основой optimizer AutoTrace.
