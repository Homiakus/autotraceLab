# AutoTrace Process Math — формулы времени и статистика процессов

## Назначение

Process Math добавляет к технологическим блокам вычислимую модель времени. Для каждого этапа можно задать либо фиксированное значение с единицей измерения, либо формулу. Итоговый статистический блок агрегирует рассчитанные этапы.

В LBC Workflow Atlas модуль находится ниже инженерного drill-down и работает для каждой представленной платформы.

## Базовая модель

Все формулы вычисляются в секундах. Числовой ввод блока автоматически преобразуется из `ms`, `s`, `min` или `h`.

Каждый блок публикует переменную:

```text
<stageId>.time
```

Например:

```text
receipt.time
loading.time
enrichment.time
staining.time
```

Формула более позднего блока может ссылаться на уже вычисленные предыдущие блоки:

```text
receipt.time + 30
loading.time * 1.15
max(conditioning.time, enrichment.time)
sum(receipt.time, loading.time, conditioning.time)
```

## Операторы

Поддерживаются:

```text
+  -  *  /  ^  ( )
```

Деление на ноль, неизвестные переменные, отрицательное рассчитанное время и синтаксические ошибки приводят к явной ошибке блока, а не к скрытому `NaN`.

## Функции

```text
sum(a, b, ...)
avg(a, b, ...)
min(a, b, ...)
max(a, b, ...)
round(x)
ceil(x)
floor(x)
abs(x)
sqrt(x)
```

Парсер не использует `eval`, `Function` или выполнение произвольного JavaScript.

## Переменные итогового блока

После расчёта процесса доступны:

```text
total.time
automatic.time
manual.time
mixed.time
wait.time
external.time
qc.time
bottleneck.time
coverage.percent
batch.count
```

Примеры пользовательской итоговой формулы:

```text
total.time / batch.count
batch.count / (total.time / 3600)
automatic.time / total.time * 100
max(enrichment.time, staining.time)
```

## Автоматическая статистика

Σ-блок показывает:

- суммарное последовательное время `T = Σtᵢ`;
- ручное, автоматическое, смешанное, внешнее и QC-время;
- долю автоматического времени;
- процент этапов, для которых задан вычислимый тайминг;
- самый длительный этап (bottleneck);
- модельную производительность партии `Q = N / T`;
- пользовательскую формулу.

Текущая модель критического пути предполагает последовательную цепочку. Для параллельных ветвей инженерный принцип — `Tcritical = max(Tbranch1, Tbranch2, ...)`; будущая интеграция в общий граф AutoTrace может вычислять critical path непосредственно по DAG.

## LBC Engineering Drill-down

Добавлен второй масштаб схемы. В зависимости от платформы крупный блок раскрывается в технологическую последовательность:

- ThinPrep: диспергирование → мембранный сбор → feedback по потоку → перенос на стекло → фиксация;
- SurePath/Totalys: Density Reagent → центрифугирование → удаление супернатанта → pellet → ресуспендирование → седиментация;
- EASYPREP/CytoReference/LTS: центрифугальное обогащение → ресуспендирование → осадочная камера → при наличии интегрированная Pap-окраска;
- CellPrep/HURO PATH/CellSlide: мембранный сбор → контроль нагрузки → обратный перенос → фиксация;
- NOVAprep: роботизированное дозирование → differential/double decantation → концентрированная фракция → нанесение.

Для понимания физики рядом могут показываться инженерные зависимости:

```text
RCF = 1.118·10⁻⁵ · r(cm) · rpm²
J = ΔP / (μ · Rtotal)
v ≈ 2(ρp−ρf)gr² / (9μ)
T = Σtᵢ
Q = N/T
A = ΣTauto / ΣTprocess
```

Эти уравнения предназначены для моделирования и объяснения зависимостей. Они не заменяют IFU/SOP и не должны использоваться для самостоятельного восстановления или изменения клинически валидированных RPM, давления, времени центрифугирования или рецепта окраски.

## Проверка

`src/tests/processMathTest.ts` проверяет:

- приоритет арифметических операций;
- функции `max` и `avg`;
- ссылки на переменные этапов;
- отказ при делении на ноль;
- перевод минут в секунды;
- зависимый тайминг следующего блока;
- итоговое время и breakdown по автоматизации;
- bottleneck;
- расчёт производительности партии.

Frontend CI выполняет:

```text
npx tsc -p tsconfig.frontend.json --noEmit
npx tsx src/tests/processMathTest.ts
npm run build
```
