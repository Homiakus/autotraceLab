# Resource-Constrained Process Simulation

Этот режим расширяет Process Math от статического анализа DAG до детерминированной дискретно-событийной симуляции нескольких образцов/заказов, которые одновременно проходят один и тот же процесс и конкурируют за ограниченные ресурсы.

## Запуск

После `npm run dev`:

```text
http://localhost:3000/?view=process-sim
```

или:

```text
http://localhost:3000/#process-sim
```

## Что моделируется

Для каждого блока уже существующего Process Math используются:

- продолжительность операции;
- зависимости DAG;
- тип операции;
- набор требуемых ресурсов.

Отдельно задаются ресурсы:

- оператор;
- процессор/автомат;
- центрифуга;
- станция окраски;
- QC-станция;
- любая другая пользовательская единица.

У ресурса есть `capacity` — число одинаковых единиц, способных работать параллельно.

Пример:

```text
Оператор × 1
Центрифуга × 2
Stainer × 1
```

Если операция требует `Центрифуга × 1`, две такие операции могут идти одновременно. Третья будет ждать освобождения одной позиции.

## Модель партии

Параметры:

- `batchSize` — число образцов;
- `releaseIntervalSeconds` — интервал поступления образцов в модель;
- `requirementsByBlock` — какие ресурсы и в каком количестве одновременно нужны блоку.

При `releaseIntervalSeconds = 0` вся партия доступна с момента `t=0`.

## Планировщик

Используется list-scheduling над DAG с ресурсными календарями.

1. Для каждого образца создаётся экземпляр каждого блока.
2. Операция становится кандидатом, когда запланированы все её предшественники.
3. `ready time` равен максимуму:
   - момента поступления образца;
   - времени завершения зависимых операций.
4. Для каждого требуемого ресурса ищется самый ранний интервал, в котором одновременно доступно нужное число единиц.
5. Из доступных задач выбирается задача с самым ранним допустимым стартом.
6. Ресурсные интервалы резервируются, после чего открываются последующие узлы DAG.

Календарь ресурса состоит из отдельных lanes по числу `capacity`, поэтому планировщик умеет вставлять операции в свободные интервалы, а не только добавлять их в конец очереди.

## Метрики

### Makespan

Время от `t=0` до завершения последнего образца партии.

### Cycle time

Для каждого образца:

```text
completion - release
```

Показываются среднее значение и P95.

### Queue / wait time

Для операции:

```text
start - ready
```

Это время, которое появляется именно из-за занятости ограниченного ресурса.

### Batch throughput

```text
Q_batch = batchSize / makespan
```

В интерфейсе пересчитывается в образцы/час.

### Output rate

Для партии более одного образца дополнительно считается наблюдаемая скорость выхода после первого завершённого образца:

```text
Q_output = (N - 1) / (t_last - t_first)
```

Она лучше показывает установившийся конвейерный темп, чем простое деление размера партии на makespan.

### Resource utilization

Для ресурса ёмкости `C`:

```text
U = busy_unit_time / (C × makespan)
```

Ресурс с максимальной загрузкой помечается как resource bottleneck.

## Импорт Process Math

Кнопка `Импорт текущего Process Math DAG` читает последнюю сохранённую модель универсального Process Math Workbench и переносит:

- блоки;
- формулы времени;
- зависимости;
- размер партии.

Стартовые ресурсы назначаются по типу блока:

- `manual` → оператор;
- `automatic` → автомат;
- `mixed` → оператор + автомат;
- `wait` → ресурс не нужен;
- `external` → внешний модуль;
- `qc` → QC-станция.

Это только первоначальное предположение. Пользователь может заменить его реальными ресурсами конкретной линии.

## LBC-шаблоны

Все LBC-платформы, уже представленные в сравнительном атласе, доступны как стартовые process templates.

Важно: если в исходных данных производителя отдельное время этапа не опубликовано или задано диапазоном, симулятор не придумывает среднее значение. Такой блок остаётся неразрешённым до явного ввода времени пользователем.

## Что эта модель уже позволяет исследовать

Например, сравнить сценарии:

```text
1 оператор + 1 процессор + 1 stainer
2 оператора + 1 процессор + 1 stainer
1 оператор + 2 процессора + 1 stainer
1 оператор + 1 процессор + 2 stainer
```

и увидеть, какой дополнительный ресурс действительно уменьшает makespan и очередь, а какой почти ничего не меняет.

## Ограничения текущей версии

Модель детерминированная. Пока не учитываются:

- случайное распределение времени операций;
- аварии оборудования и MTBF/MTTR;
- смены персонала и календари доступности;
- batch-only ресурсы, запускающиеся только после заполнения корзины;
- setup/changeover между типами образцов;
- приоритеты срочных образцов;
- rework / повторное изготовление стекла;
- вероятностный QC reject;
- транспортные времена между физическими станциями.

Это следующие естественные расширения движка.

## Безопасность применения к LBC

Симулятор предназначен для инженерного анализа лабораторного потока, очередей и загрузки оборудования. Он не заменяет валидированные протоколы производителя и не должен использоваться для самостоятельного изменения клинически валидированных RPM, давления, времени реагентных стадий или иных параметров медицинского изделия.
