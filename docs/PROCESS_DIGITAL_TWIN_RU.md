# Process Digital Twin — стохастическая DES-модель

Режим:

```text
/?view=process-digital-twin
```

или:

```text
/#process-digital-twin
```

## Зачем нужен этот уровень

Обычный Process Math описывает детерминированный DAG. Resource Simulation добавляет ограниченные ресурсы. Batch Simulation добавляет общие циклы оборудования. Process Digital Twin моделирует вариабельность **на уровне конкретной пробы**.

Если для этапа задано `60 s ±20%`, две разные пробы больше не обязаны получить одно и то же время. Каждая операция каждой пробы получает собственное значение из распределения. Поэтому меняется фактическая последовательность захвата ресурсов и очередь.

## Входной поток

Поддерживаются два режима:

- `fixed` — постоянный интервал между пробами;
- `poisson` — экспоненциально распределённые интервалы поступления с заданным средним интервалом.

Poisson-поток воспроизводится через `seed`.

## Вариабельность этапов

В UI задаётся симметричный triangular-разброс `±%` вокруг базового времени блока.

Например:

```text
Базовое время: 120 s
Разброс: ±25%

min  = 90 s
mode = 120 s
max  = 150 s
```

Sampling выполняется отдельно для каждой пробы и каждой повторной попытки.

## Rework

Для каждого блока задаются:

- вероятность повторной обработки;
- максимальное число повторов.

Если rework срабатывает, downstream-блоки этой пробы не запускаются. Тот же этап снова становится готовым после завершения предыдущей попытки и повторно конкурирует за ресурсы.

## Приоритет STAT

STAT имеет более высокий queue priority. Политика **не является preemptive**: уже начатая операция не прерывается. Если несколько готовых задач претендуют на один следующий свободный слот ресурса, STAT выбирается первой.

В текущем UI можно задавать правило `каждая N-я проба = STAT`.

## Метрики

Digital Twin выводит:

- makespan;
- average и P95 cycle time;
- average и P95 queue wait;
- throughput и steady output rate;
- общее число rework;
- rework rate;
- average cycle для STAT и routine;
- STAT advantage;
- utilization и peak units каждого ресурса;
- bottleneck resource;
- статистику длительности/ожидания/rework по каждому этапу;
- timeline первых операций.

## Воспроизводимость

При одинаковых:

- DAG;
- ресурсах;
- uncertainty;
- arrival policy;
- rework policy;
- priority policy;
- `seed`

результат симуляции должен быть одинаковым.

Это проверяется unit test.

## Текущая граница модели

Эта версия Digital Twin моделирует **поштучные операции**. Общие batch-cycle стадии (ротор, rack, stainer-batch) уже существуют в отдельном Batch Simulation engine, но пока не объединены с per-sample stochastic scheduler в одном движке.

Следующий шаг — unified stochastic batch DES, затем календари смен, плановые окна недоступности и MTBF/MTTR оборудования.
