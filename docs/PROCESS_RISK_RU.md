# Process Risk & Capacity Planner

Этот режим строится поверх Resource-Constrained Process Simulation и отвечает на два вопроса:

1. насколько устойчивы makespan / cycle time / throughput к вариабельности времени операций;
2. какой один дополнительный ресурс даёт наибольший системный выигрыш.

## Запуск

```text
http://localhost:3000/?view=process-risk
```

или:

```text
http://localhost:3000/#process-risk
```

Режим читает последнюю сохранённую модель `Process Simulation` из Local Storage.

## Monte Carlo

Для каждого блока задаётся относительный разброс времени `±p%`.

При `p > 0` используется треугольное распределение:

```text
min  = base × (1 - p)
mode = base
max  = base × (1 + p)
```

При `p = 0` блок остаётся детерминированным.

Каждая итерация:

1. воспроизводимо генерирует длительности по заданному seed;
2. запускает полную ресурсно-ограниченную симуляцию партии;
3. сохраняет makespan, средний cycle time, throughput и среднее ожидание.

Далее рассчитываются P50, P90, P95 и P99.

### Seed

Используется детерминированный PRNG. Одинаковые:

- модель;
- параметры неопределённости;
- число итераций;
- seed

дают воспроизводимый результат.

### SLA confidence

Если задан SLA по makespan, считается:

```text
P(SLA) = successful_runs_with_makespan_<=_SLA / completed_runs
```

Эта величина показывает долю моделируемых сценариев, укладывающихся в SLA.

## Capacity sensitivity planner

Для каждого ресурса выполняется отдельный what-if сценарий:

```text
capacity_candidate = capacity_current + 1
```

Остальная модель не меняется.

Сравниваются:

- makespan;
- throughput;
- среднее ожидание;
- utilization ресурса после увеличения capacity.

Сценарии ранжируются по составному sensitivity-score:

```text
score = 0.45 × makespan_reduction%
      + 0.40 × throughput_gain%
      + 0.15 × max(0, wait_reduction%)
```

Это инженерный рейтинг системного эффекта, а не финансовая рекомендация.

## Интерпретация

Если увеличение ресурса с `capacity=1` до `2` почти не меняет makespan и throughput, этот ресурс не является текущим ограничением системы.

Если изменение резко уменьшает очереди и makespan, ресурс является хорошим кандидатом для дальнейшего технико-экономического анализа.

Важно различать:

- **critical-path bottleneck** — длинная операция в DAG;
- **resource bottleneck** — наиболее занятый ресурс;
- **capacity-sensitive bottleneck** — ресурс, увеличение которого реально улучшает системный результат.

Это три разных понятия.

## Ограничения

Текущая Monte Carlo модель варьирует длительности операций, но пока не моделирует отдельно:

- случайные отказы оборудования;
- MTBF / MTTR;
- повторное изготовление/rework;
- вероятность QC reject;
- сменные календари операторов;
- batch-start policy для корзин/роторов;
- changeover/setup между типами образцов;
- случайный процесс поступления образцов.

Эти факторы можно последовательно добавить поверх существующего движка.

## Применение к LBC

Risk/Capacity Planner предназначен для анализа организации лабораторного потока. Разброс времени должен описывать наблюдаемую организационную/операционную вариабельность и не должен использоваться как основание для изменения валидированных параметров медицинского изделия или реагентного протокола производителя.
