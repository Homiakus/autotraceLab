# AutoTrace Process Math Workbench

## Назначение

`Process Math Workbench` — универсальный слой расчётов для технологических и инженерных процессов. Его задача — связать математические параметры непосредственно с визуальными блоками процесса.

Открытие в dev-режиме:

```text
http://localhost:3000/?view=process-math
```

или:

```text
http://localhost:3000/#process-math
```

## Модель блока

Каждый блок содержит:

- `id` — внутренний уникальный идентификатор;
- `key` — человекочитаемый математический ключ;
- `title` — название операции;
- `automation` — тип выполнения;
- `time.value + time.unit` — фиксированное время;
- `time.formula` — альтернативная формула времени;
- `dependencies[]` — блоки, которые должны завершиться до запуска текущего.

Если заполнена формула, она имеет приоритет над фиксированным временем.

### Единицы

Поддерживаются:

- `ms`;
- `s`;
- `min`;
- `h`.

Внутри математического движка всё нормализуется в секунды.

## Ссылки между блоками

Если блок имеет математический ключ:

```text
prep
```

то его рассчитанное время доступно другим формулам как:

```text
prep.time
```

Пример:

```text
prep.time + 30
```

означает «время блока `prep` плюс 30 секунд».

Порядок карточек на экране не определяет математическую зависимость: движок выполняет фиксированную итерационную резолюцию формул и может разрешить ссылку на блок, расположенный позже в UI, если зависимость вычислима.

## Поддерживаемые операции

Безопасный parser не использует `eval`.

Операторы:

```text
+ - * / ^
```

Функции:

```text
sum(...)
avg(...)
min(...)
max(...)
round(x)
ceil(x)
floor(x)
abs(x)
sqrt(x)
```

Деление на ноль, отрицательное время, неизвестные переменные и некорректный синтаксис возвращаются как ошибка блока.

## Зависимости и DAG

`dependencies[]` описывает причинно-временной граф процесса.

Например:

```text
A -> B -> D
 \-> C -/
```

означает, что `B` и `C` могут выполняться после `A` параллельно, а `D` запускается только после завершения обеих ветвей.

Поэтому Workbench различает два показателя:

### Сумма времён

```text
T_sum = Σ t_i
```

Полезна для оценки общей занятой длительности операций/ресурсов, но завышает календарное время при параллельных ветвях.

### Критический путь

```text
T_critical = max(path duration)
```

Это минимальное календарное время завершения DAG при предположении, что независимые ветви могут выполняться параллельно и ресурсные ограничения не мешают параллелизму.

Циклы в графе автоматически обнаруживаются и выводятся как ошибка модели.

## Итоговый Σ-блок

Итоговый блок рассчитывает:

- сумму времён всех рассчитанных блоков;
- критический путь;
- ручное время;
- автоматическое время;
- смешанное время;
- ожидание;
- внешние операции;
- QC;
- процент блоков с заданным временем;
- долю чисто автоматического времени;
- самый длительный отдельный блок — bottleneck;
- модельную пропускную способность партии.

### Throughput

В текущей модели:

```text
Q = batch.count / (T_critical / 3600)
```

где `Q` выражается в партиях/образцах в час в зависимости от смысла `batch.count`.

Это модельная оценка. Для реальных конвейеров с перекрывающимися партиями, несколькими приборами и ограниченными ресурсами понадобится отдельная дискретно-событийная модель.

## Переменные Σ-блока

Доступны:

```text
total.time
critical.time
manual.time
automatic.time
mixed.time
wait.time
external.time
qc.time
bottleneck.time
batch.count
throughput.hour
coverage.percent

```

Примеры:

```text
total.time / batch.count
```

```text
critical.time / batch.count
```

```text
automatic.time / total.time * 100
```

## LBC-шаблоны

Workbench может загрузить любую из LBC-платформ, описанных в проекте, как стартовую модель.

При импорте времени из текстового описания используется консервативное правило: однозначно опубликованное значение может быть автоматически распознано, а диапазоны не превращаются искусственно в среднее значение.

Если у производителя отдельное время операции не опубликовано, поле остаётся пустым до ввода валидированного значения пользователем.

## Сохранение и обмен

Модель автоматически сохраняется в браузере через Local Storage.

Доступны:

- экспорт JSON;
- импорт JSON;
- дублирование блоков;
- изменение порядка отображения;
- независимое редактирование зависимостей.

## Следующие архитектурные шаги

1. Встроить `Process Math` как свойство обычного `BlockNode` в основном AutoTrace Canvas.
2. Отображать рассчитанное время и формулу прямо внутри SVG-блока.
3. Добавить тип блока `Statistics / Σ` в палитру создания узлов.
4. Рассчитывать upstream-подграф для каждого Σ-блока, а не только одну модель целиком.
5. Добавить ресурсные ограничения: один оператор, одна центрифуга, один стейнер и т. п.
6. Перейти от одного DAG critical path к discrete-event simulation для пакетных производственных процессов.
7. Добавить Monte Carlo для времени, заданного распределениями, а не одной точкой.
8. Добавить sensitivity analysis и автоматическое ранжирование «какой этап выгоднее автоматизировать первым».

## Ограничение для медицинского оборудования

Математический слой предназначен для описания и анализа процесса. Он не заменяет IFU, валидированный лабораторный SOP и зарегистрированные параметры медицинского оборудования. Расчётные формулы нельзя использовать как основание для самовольного изменения RPM, давления, времени фиксации, режимов окрашивания или других валидированных технологических параметров.
